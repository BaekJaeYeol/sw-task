## 이 작업에 적용하는 것
**원문·제출본·구현 상태 분리.** 실물 제작·구매·성능 시험을 문서 작성과 혼동하지 않는다. Arduino UNO R3 제외 조건을 유지한다.

| 역할 | 맡는 일 | 하지 않는 일 |
|---|---|---|
| 기획 | 기존 작업·결정 확인, 다음 작업과 의존성 정리 | 완료 기준 없는 작업 확대 |
| 실행·검토 | 지정 범위 수행, 실제 결과·실패·다음 행동 기록 | 권한 우회·근거 없는 완료 처리 |

한 세션에서 두 역할을 순서대로 수행해도 된다. 역할 정의는 하위 에이전트·상주 프로세스·새 계정 연결 권한을 부여하지 않는다.

## 실제 다음 작업 카드
- ID: `OPS-SW-TASK-001`
- 상태: **할 일** (앱·운영 기능을 이번 문서 변경으로 완료 처리하지 않음)
- 할 일: 보고서 본문과 제출본의 학번·제출일·팀 인원·미견적 항목을 대조한다.
- 완료 기준: 대상 브랜치·커밋, 입력과 예상/실제 결과, 오류/중단 결과와 근거 위치가 남아 있다. Windows·브라우저·계정 연동 등 실행하지 못한 검사는 미검증으로 분리한다.
- 검토: 실제 결과를 완료 기준과 대조한 담당. 문서를 읽은 것과 실제 테스트는 구분한다.

## 결정·직접 수행·기다림
현재 새 사용자 답변이 필요한 항목은 등록하지 않았다. 기존 승인 범위에서 가능한 작업부터 진행한다. 필요 시 원본 Issue/카드에 `OPS-SW-TASK-DEC-<고유값>` / `MAN-<고유값>` / `WAIT-<고유값>`을 주고 질문·추천·이유·유효 조건·담당을 남긴다. 답을 받은 담당은 선택만 기록하고 실행 담당이 최신 원본과 중복 여부를 확인한다. 선택됨은 실행 완료가 아니다.

## 기억·중단·성공 판정
- 기존 Issue·설계·검증 문서·DI 문맥이 원본이다. 별도 DB를 만들거나 중앙에 원문을 복제하지 않는다.
- 작업 종료 또는 중단 시 원본 버전, 정한 것과 이유, 실제 된 것/안 된 것, 다음 행동을 기존 기록에 남긴다. 해당 기록이 없을 때만 로컬 작업 노트를 쓴다.
- 완료 단계는 입력 버전과 산출물을 대조하고, 입력이 바뀌어 무효화된 단계만 다시 검사한다. 무조건 처음부터 재시작하지 않는다.
- 마지막 시도·마지막 성공·원본 갱신·화면 생성 시각을 구분한다. 조회 실패를 빈 결과로 바꾸거나 최근 로그만으로 정상이라고 하지 않는다.
- 실패한 항목과 재시도 상한을 기록한다. 통신 시간 초과 뒤에는 실제 반영을 먼저 확인하고 같은 게시·주문·파일 생성을 추측해 반복하지 않는다.
- GitHub Actions는 사용자에게 먼저 확인한 경우에만 사용한다. 이 적용에서는 실행하지 않는다. 테스트 결과와 원격 CI·실제 운영은 별도다.

## 이번 적용의 확인 범위
프로젝트별 지침 연결·원본/후보 구분·다음 작업/완료 기준 설정을 적용했다. 문서 구조·연결 검사는 [전체 적용 장부](https://github.com/BaekJaeYeol/project-automation/blob/main/docs/operations/rollout.md)에서 추적한다. 애플리케이션 전체 실행·배포·설치·상시 운영·개인 자료 변경은 수행한 것으로 간주하지 않는다.
